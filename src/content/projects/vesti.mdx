## 问题：对话会消失，思考不应该

重要的 AI 对话通常散落在 ChatGPT、Claude、Gemini 等不同平台里。平台保存了消息，却没有形成属于用户的连续记忆；当工具、账号或工作流改变时，过去的判断也很容易随之失去。

Vesti 把这个问题定义为一个“记忆层”问题，而不只是聊天记录导出问题。它尽量不改变用户原本的工具与标签页，只在浏览器中增加一个可搜索、可迁移的个人档案。

## 产品模型

Vesti 不是一块不断增加功能的仪表盘，而是两种彼此连接的工作空间：

- **浏览器扩展**：Threads、Insights、Data 与 Settings 靠近对话发生的地方，负责捕获、快速回看和系统控制
- **知识工作台**：Library、Explore 与 Network 负责阅读原始线程、形成笔记、追问档案并观察关系随时间出现

两种空间共享来源、线程与状态模型，但承担不同的信息密度。Reader 始终属于线程的下钻，而不是另一个顶层目的地。

## 设计原则

### 不制造第二个工作流

记忆层应当贴近内容产生的地方。侧栏与覆盖层保持克制，让正在进行的聊天仍然是主界面。

### 本地优先是一种产品立场

默认把档案和索引保留在浏览器附近，减少对另一个云端账户的依赖。可迁移、可删除与可逆，不是设置页里的附加选项，而是信任模型的一部分。

### AI 增强判断，而不是替代判断

自动整理的价值在于帮助用户回到自己的材料、比较过去的思路并发现联系，而不是制造一个看似确定的总结终点。

当前公开 Prompt Eval baseline 是 **10 个 deterministic mock cases**（7 个 conversation、3 个 weekly），用于检查结构化输出与必需字段，不是线上模型质量基准。Nightly live workflow 因缺少模型密钥而实际跳过，因此目前不公开宣称任务成功率、线上延迟或成本指标。

## Problem: conversations disappear, thought should not

Important AI conversations are scattered across ChatGPT, Claude, Gemini, and other platforms. Platforms retain messages, but rarely create a continuous memory owned by the user. When tools, accounts, or workflows change, past judgement is easily lost with them.

Vesti frames this as a memory-layer problem rather than a transcript-export problem. It preserves the user's existing tools and tabs, adding a searchable and portable personal archive inside the browser.

## Product model

Vesti is organised as two connected working spaces rather than a dashboard that accumulates features:

- **Browser extension**: Threads, Insights, Data, and Settings stay close to where conversations happen, handling capture, quick return, and system control
- **Knowledge workspace**: Library, Explore, and Network support source reading, note-making, archive questions, and relationships unfolding over time

The two spaces share provenance, thread, and state models while carrying different densities. Reader remains a drill-down from a thread rather than another top-level destination.

## Design principles

### Do not create a second workflow

Memory should remain close to where it is made. Restrained side panels and overlays preserve the active conversation as the primary interface.

### Local-first is a product position

Keeping archives and indexes near the browser reduces dependence on yet another cloud account. Portability, deletion, and reversibility are part of the trust model rather than optional settings.

### AI augments judgement

Automatic organisation should help people return to their own material, compare earlier thinking, and notice relationships—not manufacture a falsely definitive endpoint.

## Current form

Vesti now includes a browser extension, conversation archive, search and exploration surfaces, and a visual system shared across interface and print. The canonical repository continues to be maintained by the team; my repository is a public snapshot rather than the latest source.

## Evaluation and known boundaries

The public Prompt Eval baseline currently contains **10 deterministic mock cases**—seven conversation cases and three weekly cases. It checks structured-output contracts and required fields; it is not a live model-quality benchmark. The nightly live workflow is skipped without model credentials, so this case does not claim task success, production latency, or cost metrics.

The next verification work concerns long-term retrieval quality, cross-device portability, parser resilience as source platforms change, and live-model measurements for bad cases, fallback, P50/P95 latency, and per-task cost.
